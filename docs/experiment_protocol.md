# Agent Benchmark 实验协议

## 运行与配对条件

`python scripts/run_agent_benchmark.py --seed 46001 --variants 3` 为每次运行建立 `artifacts/benchmarks/<run_id>/`。数据由固定配置生成，包含夜景、HDR、运动、强噪声、鬼影、错位、过曝、欠曝、Bayer 错配和常规对照十类，每类三个种子或条件变体。多数样例共享同一个解析场景生成器，配准样例使用单独的已校准纹理。输入、Ground Truth、种子和每次摄影结果随运行落盘。数据范围限于合成样例。

每个任务的五个方案共享同一个 RAW 产物、顺序、曝光元数据、P3 图像工具、裁剪区域和参考坐标。已知平移、Bayer 错配和首轮故障注入对同一任务的所有方案一致。鬼影样例首轮关闭去鬼影，错位样例首轮关闭配准。报告中将这些样例作为阶段故障恢复测试。其余样例使用各模式的常规初始设置。

| 方案 | 实际执行 |
| --- | --- |
| Fixed Pipeline | 固定 Night 模式，执行一次摄影工具和一次 IQ 工具 |
| Single Agent | 单控制器读取场景观测和用户目标，选取模式，执行一次摄影与 IQ |
| Multi-Agent without Feedback | 运行实际 LangGraph，关闭反馈与记忆读取，执行一次摄影与 IQ |
| Multi-Agent with Debugging Feedback | 同一 LangGraph，开启证据验证与重处理，关闭记忆读取 |
| Multi-Agent with Experiment Memory | 同一反馈图，另外从隔离的历史库检索成功案例 |

记忆训练使用三个独立种子的真实鬼影修复任务。预热采用较灵敏的运动阈值，训练记录和训练产物存于本次运行的 `training/`。待评任务写入另一实验库，期间不加入供记忆读取的训练库。方案执行顺序按任务轮换。固定一个 OpenCV 线程，所有方案使用相同的已注册、经 Pydantic 校验的本地工具实现。Benchmark 测量进程内调用耗时，生产工作流的进程启动、超时及重试以 pytest 单独验收。Runtime 从方案起点到状态与产物写出，包含读写和调试开销，不含共享数据准备与外部验收评分。

## 独立成功门槛

任务通过同时要求发布结果、执行正确模式的摄影工具，并满足对应场景目标。模式金标随场景定义，评分以实际产物中记录的模式和成功工具记录为准。每个任务使用其指定参考帧的单 RAW 结果作为基线，光度比较统一到场景线性辐亮度。

| 类别 | 图像或参数验收门槛 |
| --- | --- |
| Night / Noise / Control | 平滑暗部 Noise STD 分别不高于单帧的 97% / 93% / 105%，PSNR 下降最多 0.25 dB |
| HDR / Overexposure | 参考帧裁剪区 RMSE 不高于单帧的 93% |
| Underexposure | 静态暗部 RMSE 不高于单帧的 90% |
| Motion / Ghosting | 移动物体扫掠区域 RMSE 不高于单帧的 110% |
| Registration | 恢复预设偶数像素平移，误差不超过 1 px |
| Bayer | 恢复由生成器记录的实际 CFA 排列 |

PSNR 以场景 Ground Truth 的最大值或 1 为峰值，SSIM 在同一色域计算。Noise STD 是平滑静态暗部亮度误差的标准差，Ghost RMSE 是真实运动区域 RGB 的均方根误差。区域至少 32 个支持像素，缺失区域留空。图表逐任务连线用于比较配对结果，横轴为分类顺序，无连续时间或收敛含义。单组均值列包括各自有效样本数。

Tool Selection Accuracy 衡量对场景期望摄影模式的实际执行率。诊断另以已知注入故障为分母，记录经工具确认的标签命中。验证修复要求已标注的故障经工具确认，首轮独立指标未通过，重处理后按同一条件通过。指标溯源率要求有效值含具体测量方法和对应的最终产物 ID。配对 PSNR 改变以每个任务的固定流水线为基线，先求差再汇总。

## 补充实验

- **采集策略** 在三个独立场景实际拍摄模拟 Fixed、亮度规则和 Agent Planner 的计划，表格列参考帧码值、饱和比例、曝光内位移、耗时和输入产物。计划会改变曝光条件和帧数，该表检查采集权衡，不用于架构成功率。
- **摄影流水线** 对反馈方案选中的同一 Burst，从摄影产物读取单帧、经相同预处理的单帧、曝光归一化平均、关闭去鬼影的配准融合和最终融合的实际评分。每行保存对应的摄影产物 ID。
- **诊断与架构** 使用可审计的 30 个冻结任务、逐任务工具轨迹和五种架构配对对照。当前报告给出描述统计、分母和失败场景，不从三个变体推断统计显著性。
